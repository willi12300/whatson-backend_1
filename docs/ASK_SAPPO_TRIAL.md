# Ask SAPPO trial

`POST /ask-sappo` accepts a message (up to 600 characters), up to three earlier user requests, Liverpool as the city, a future ISO startAt within six days, and 60–360 available minutes. Coordinates are optional and constrained to the Liverpool area. Gemini uses the existing server-only GEMINI_API_KEY to interpret up to three activities: coffee, walk, sunset, food, culture or drink. It supplies no venue facts or user-facing factual prose. Event listings and other unsupported requests receive a clarification.

The server selects existing catalogue records, excludes known closures, checks published opening-hour periods at arrival, and explicitly labels unknown hours. Long walks favour a small allowlist of substantial Liverpool parks and waterfront areas. Sunset locations use a separate local allowlist; the view and clear skies are not guaranteed. Google Routes supplies walking travel when available; otherwise distance estimates are labelled. Exploration time at a park is not a mapped walking circuit. Fresh destination Open-Meteo forecasts supply hourly weather; fallback and stale weather is suppressed. Stops can be partial when the requested activity or timing cannot be satisfied.

Successful intent interpretations are cached for ten minutes (up to 200 entries); identical concurrent requests share one call. Each uncached interpretation makes at most two Gemini attempts: gemini-2.5-flash first, and gemini-3.1-flash-lite when the primary is quota-exhausted, unavailable, timed out or retired. Each attempt has a 400-token output cap and disabled (2.5) or minimal (3.1) thinking; both count towards the same daily attempt ceiling. The route permits eight requests per IP per minute and 100 Gemini attempts per UTC day per running API instance by default. ASK_SAPPO_DAILY_LIMIT can lower the latter or set it to 0 to stop new AI calls. In-memory ceilings reset on restart and multiply across instances: these are trial request limits, not a hard monetary budget. Configure provider billing budgets separately. Other existing Gemini endpoints have their own behaviour and are not included in this counter. Each plan may additionally make up to three walking Routes requests and cached weather requests.

The UI identifies this as a Gemini trial, explains request sharing, and makes no bookings. Conversation history stays in component memory and is sent only when asking for an outing/refinement. The backend intent cache temporarily retains those request strings in process memory for ten minutes; they are not logged or written to the database. Saved stops use the existing device-local Plans storage, with their arrival date/time. Reordering a saved outing invalidates the original schedule.

Gemini failures are classified without exposing raw provider messages, credentials or project identifiers. GET /ask-sappo/status reports the last observed status and per-model cooldowns without calling Gemini. On failure, calls to the failing model pause for at least a minute, respecting provider retry hints (up to an hour). Simple supported requests use a clearly labelled, deterministic basic mode with the same catalogue, route, hours and weather checks. Complex constraints and unsupported requests ask for clarification instead of guessing. Basic mode also remains available when the local daily AI ceiling is reached. This does not restore a revoked key or increase a provider quota.
